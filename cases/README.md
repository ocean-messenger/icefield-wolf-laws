# 案例库

## 免责声明

本案例库是所有读者的自由思考区。

在这里分享的内容，全部是读者自己的感悟和运用。
项目维护者没有参与任何具体案例的发言和思考。

如果某位读者从狼群故事中学到了什么，那是这位读者自己厉害。
如果某位读者把学到的用在了自己的领域，那也是这位读者自己的事。

本项目只提供故事，不提供结论。
本项目只提供法则，不提供用法。
本项目只提供案例，不提供评判。

所有案例仅代表投稿者个人观点，不代表本项目立场。

---

## 结界：禁止讨论区

以下话题一律不得在案例库中出现，包括但不限于：

- 社会制度比较
- 历史规律总结
- 历史运动评价
- 国际局势分析
- 现行政策评论
- 任何国家、政党、领导人的直接评价
- 任何民族、宗教、种族的比较
- 任何涉及现实政治人物的类比
- 其他可能引发对立、争议、或超出项目范围的宏大叙事

一旦出现，PR 直接关闭，不讨论、不解释、不妥协。

这不是审查，这是保护。保护这个项目能活下去，保护投稿者不被牵连。

---

## 我们鼓励什么

我们鼓励从**当时完整的情境**出发，分析一个合作系统内部发生了什么。

就像高中写议论文那样：

- 可以分析“为什么我们需要这样合作”
- 可以分析“为什么这个团队会散”
- 可以分析“为什么这个决策会崩”

但我们**不做**以下事情：

- 不上升层次到“阶级就是剥削”
- 不上升层次到“历史必然规律”
- 不上升层次到“某种制度必然灭亡”

分析可以深，但层次不能太高。
就事论事，就团队论团队，就案例论案例。

---

## 推荐机制（不是淘汰机制）

案例库不是考试，没有及格线。

- 所有不越界的投稿都会被保留
- 大家觉得好的案例，会被推荐到显眼位置
- 大家觉得一般的案例，也保留在库里，作为素材
- 甚至，差的案例可以作为“驳论文素材”存在

我们不淘汰差的见解。
差的见解只要不越界，它自有它的用处：
它鼓励了投稿积极性，它甚至能够作为素材写驳论文。

**推荐机制**：

- 用 GitHub 的 👍 / 👎 reaction 表达态度
- 👍 多的，被推荐到 `featured/` 目录
- 👎 多的，留在 `submitted/`，但不会删除
- 如果有人愿意写反驳文章，反驳文章本身也可以作为新案例投稿

---

## 案例格式

每个案例建议包含（但不强制）：

1. **案例背景**：发生了什么
2. **外部触发**：表面原因是什么
3. **内部过程**：用本框架解释，内部发生了什么
4. **对应机制**：对应故事里的哪条推论或哪幅图
5. **一句话总结**

不要求完美，不要求成熟。
只要不越界，就可以投。

---

## 投稿流程

1. 在 `submitted/` 目录下新建文件
2. 文件名格式：`案例名-投稿者ID.md`
3. 提交 Pull Request
4. 社区用 👍 / 👎 表达态度
5. 👍 多的被移到 `featured/`，其余保留在 `submitted/`

---

## 复审机制

- 任何人可对 `featured/` 里的案例发起 issue，提出异议
- 异议有理有据的，重新进入讨论
- 讨论后，由社区决定是否移回 `submitted/`

## 目录结构
